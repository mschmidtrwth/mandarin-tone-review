# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An Android app (package `com.example.mandaring`, Compose, minSdk 30) for practising Mandarin tones. The user records a word, the app tracks the pitch, draws the contour against their own tone levels, overlays a native reference ("ghost"), recognises the tones, and schedules words for practice.

## Commands

```
./gradlew :pitch:test                                   # all pitch-library tests (plain JVM, fast)
./gradlew :pitch:test --tests '*TonesTest'              # one test class
./gradlew :pitch:test --tests '*TonesTest.someMethod'   # one test
./gradlew :app:assembleDebug                            # build the app
./gradlew :app:installDebug                             # install on connected phone
tools/show_sample.sh hao3                               # open a bundled sample in the debug build via adb
```

There is no lint setup. `app/src/test` and `androidTest` only hold the template examples; real tests live in `:pitch`.

## Architecture

Two Gradle modules:

- **`:pitch`** is a pure Kotlin/JVM library with no Android dependencies, holding all the signal processing and logic: `Yin` plus `PitchAnalyzer` (Praat-style cheapest path through YIN candidates) produce a `PitchTrack`; `PitchRange` (histogram) estimates a speaker's range and maps pitch to tone levels, giving a `Contour`; `Tones` segments words into syllables and classifies tones; `Word` parses names like `hao3chi1`; `Training` holds the spaced-repetition `Schedule`; `WavIo` and `Loudness` handle audio. Keep it Android-free so it stays testable on the JVM.
- **`:app`** is the Compose UI. `RecordViewModel` is the hub, wiring `audio/` (`Recorder`, `Player`), `data/` (file/JSON-backed stores for speaker profiles, attempts, takes, and the `ReferenceLibrary`) and `ui/` (`RecordScreen`, `PitchChart`).

Reference samples: `samples/*.mp3` (CC BY-NC-SA, see `samples/README.md`) are converted by `tools/prepare_samples.sh` (needs ffmpeg) to 16 kHz mono WAVs in `app/src/main/assets/samples/`. File names encode the word as pinyin with tone digits (`hao3chi1.wav`, neutral tone = 0) and are parsed by `Word.parse`. The `:pitch` tests also read these assets as fixtures (`/samples/<name>.wav`, see `pitch/build.gradle.kts`), so changing them can break tests. `PraatComparisonTest` compares against `pitch/src/test/resources/praat_f0.txt`, generated by `tools/praat_reference.py`.

## Scope limit

Tone recognition works for single words and tone pairs only. Whole-sentence recognition was tested and does not work (40 to 44 % accuracy); see `tools/sentence_feasibility/README.md` before attempting it. Those Python scripts are prototypes outside the app.
